# 게임 평가 지침

2026-09-21 · 사용자 제공 자료를 바탕으로 채택한 프로젝트 평가 기준

## 출처와 적용 범위

사용자가 제공한 「사쿠라이 마사히로의 게임 개발 철학: 비전과 실천의 균형」을 실무 평가 질문으로 재구성했다. 첨부는 해설 자료로 취급하며, 그 안의 인용·인물 발언·역사적 사실을 별도 원전 검증한 문서가 아니다. 아래 항목은 이 프로젝트의 평가 지침이며 사쿠라이의 공식 체크리스트가 아니다.

기획, 코어루프, 플레이 시나리오, 밸런스, 게임샷, UI·연출, 구현 리뷰에 적용한다. 기존 WP의 수용 기준과 증거 요구를 대체하거나 소급 변경하지 않는다. 기능 추가·규칙 변경은 별도 결정/WP로 확정한다.

## 최상위 원칙

**플레이어가 무엇을 즐기며, 자신의 선택이 어떤 결과를 만들었는지 이해할 수 있는가를 먼저 평가한다.**

개발자의 취향, 구현 난도, 기능 수, 누적 작업량을 재미의 근거로 삼지 않는다. 대상 플레이어와 플레이 목적을 먼저 명시한다. 초심자가 쉽게 승리한다는 이유만으로 실패 판정하지 않고, 숙련자의 선택·발견·최적화 여지가 함께 있는지 살핀다.

## 해석 원칙

- 위험은 적의 피해뿐 아니라 물자·시간·배치 기회·정보 부족도 포함한다. 예고 없이 당하는 손실을 깊이 있는 선택으로 포장하지 않는다.
- ‘의도된 불균형’은 개성 있는 강약을 뜻한다. 무한 자원·무적 전략·선택 무의미를 정당화하지 않는다.
- 수입 증가가 강자만 더 강하게 만들거나 열세 플레이어의 재편 기회를 없애는지 확인한다. 구제 수단은 제안으로 검토하며 자동으로 새 기능을 넣지 않는다.
- 히트 스톱·과장 모션은 결과 전달 수단의 예다. 대규모 디펜스에서 매 타격마다 전체 시뮬레이션을 멈추는 방식은 필수가 아니며, 가독성·조작·성능·결정론을 해치면 국소 효과 등 대안을 비교한다.
- 음향이 해당 WP 범위 밖이면 미구현/미평가로 기록한다. 리메이크·편곡의 원곡 존중 원칙은 해당 작업이 있을 때만 적용한다.
- 첫 3분은 초기 전달력을 보는 기준이다. 준비 시간 강제 제한·전체 런3분 고정·영상 전면 금지로 해석하지 않는다.
- 긍정적 태도를 이유로 결함을 숨기지 않는다. 비판은 관찰 근거와 개선 제안을 함께 기록한다.

## 평가 절차와 출력

1. 대상 플레이어·목표 경험·구현 커밋·시나리오·해상도·실행 방식을 적는다. 계획/구현, 수동 플레이/자동 입력, 실제 재실행/기존 기록을 구분한다.
2. 기능 정확성은 기존 AC로 PASS/FAIL/NOT RUN 판정한다. 오류 재현과 자동 테스트를 사용한다.
3. 플레이 경험은 위 항목별로 **충족 / 보완 필요 / 미평가 / 비해당**을 기록한다. 관찰과 해석·가설을 구분하고 근거 없는 점수 평균을 내지 않는다.
4. 가능한 경우 같은 seed·웨이브·입력 조건에서 대안을 비교한다. 인과를 검증하려는 비교는 한 요인씩 바꾸고 차이를 명시한다. 밸런스 재미는 여러 전략/시드와 사용자 관찰로 보강한다.
5. 개선점은 아래 형식으로 작성하고 영향 큰 1~3개를 다음 작업 우선순위로 정한다. 새 기능이 꼭 필요한지, 기존 표시·규칙 정리로 해결되는지도 비교한다.
6. GPT는 기획/품질 판정과 변경 제안, Claude는 구현/테스트/증거, 사용자는 스타일·체감 의견을 담당한다. 역할 간 동일 문서·기준 SHA를 공유한다. 불확실한 결정은 잠정안·담당·재평가 조건을 명시한다.

### 평가 기록 양식

| 항목 | 기록 |
|---|---|
| 대상 / 기준 | 플레이어, 목표 경험, 커밋, 시나리오 |
| 기능 정확성 | 기존 AC 판정과 실행 증거 |
| 선택과 코어루프 | E-01~07 관찰·판정 |
| 화면·연출·템포 | E-06/08~10 관찰·판정 |
| 관찰 사실 | 어느 조건에서 무엇이 발생했는가 |
| 플레이어 영향 | 이해·선택·성취·실패 복구에 어떤 영향을 주는가 |
| 개선 제안 | 무엇을 바꾸고 어떤 경험을 기대하는가 |
| 재검증 | 비교 조건·확인할 행동/화면·수치 |
| 우선순위 / 담당 | 다음1~3개 작업, GPT/Claude/사용자 역할 |
| 미평가 / 범위 밖 | 아직 보지 않은 것과 필요한 증거 |

‘테스트 통과=재미 검증 완료’, ‘쉬운 승리=실패’, ‘클릭 수 증가=선택 깊이 증가’, ‘그래픽 파일 적용=화면 완성’으로 판단하지 않는다. 기존 WP 전체 PASS는 그 WP의 필수 AC를 모두 충족했을 때만 부여한다.


## 구현 프로세스 연결

[개발 10계명](DEVELOPMENT_TEN_PRINCIPLES.md)의 T-01~10을 기획→구현→실행 검증→리뷰→후속 작업에 적용한다. 본 지침은 평가 질문, 10계명은 개발 행동과 검증 방법을 담당한다. 기존 AC를 유지하며 원칙별 관찰과 체감 효과를 별도 기록한다.
