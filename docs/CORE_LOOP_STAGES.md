# 코어 루프 확장 단계 — 콘텐츠 한 개 단위 분류와 테스트 모드

2026-09-23 · Claude Code 작성 · 분류는 제안(P-021, GPT 확인 대기), 테스트 모드는 구현 기술 결정(D-056)

[CORE_LOOP](CORE_LOOP.md)의 루프를 **한 단계에 콘텐츠 하나씩** 더해 가는 순서로 나누고, 단계마다 그 단계까지의 콘텐츠만 켜진 테스트 모드(`--stage=N`)를 만들었다. 각 테스트 모드는 이미 승인된 WP의 규칙만 쓴다. 이 문서는 새 게임 규칙·수치·범위를 정하지 않는다.

## 분류 기준

1. **한 단계 = 플레이어가 새로 보거나 할 수 있게 되는 것 하나.** 코드 모듈이 아니라 화면·행동 단위로 나눈다.
2. **앞 단계만 있으면 성립한다.** 순서는 의존 관계다. 예: 화차가 쏠 대상(적 흐름)과 쏠 자리(장승이 만든 병목)가 먼저 있어야 화차의 의미가 보인다.
3. **효과를 같은 시드의 비교로 보여 줄 수 있어야 한다.** 단계마다 "이 콘텐츠가 있을 때와 없을 때"를 자동으로 측정한다(아래 자동 확인).
4. 더 쪼개면 관찰 가능한 효과가 사라지는 곳에서 멈춘다. 봉수대만 있거나 혼천의만 있으면 공유 탐지가 생기지 않으므로 둘은 한 단계(봉수망)다.

단계 1~8은 구현돼 있고 테스트 모드가 있다. 9~10은 GPT의 DRAFT 순서(D-054)를 그대로 옮겼다. 11~13은 CORE_LOOP·GAME_DESIGN에 적힌 후보이며 순서는 정해지지 않았다. 미구현 단계를 `--stage=9`로 부르면 "WP-009 DRAFT: 아직 테스트 모드 없음"이라고 알리고 아무것도 바꾸지 않는다.

그래픽(WP-005, `--art=greybox|sample`)은 어느 단계에나 겹쳐지는 별도 축이라 단계에 넣지 않았다.

## 분류하면서 드러난 점 (제안 P-021, GPT 확인 요청)

- **플레이어 행동이 4단계에서 끊겼다가 8단계에서 돌아온다.** 1~4단계는 자유 설치 sandbox이고, 5~7단계는 WP-003 계약대로 붕괴 뒤 회수 배치 한 번만 있다. 이것이 사용자가 말한 "조작할 것이 없다"(P-019)의 구조적 원인이며 WP-008이 이를 메운다. 순서 자체는 의존 관계라 바꾸지 않았다. WP-008이 DONE이 되면 8단계를 5단계 바로 뒤로 당기는 배치(웨이브 → 준비·건설 → 붕괴)도 가능하다. 결정은 GPT 몫이다.
- **봉수망은 한 단계로 묶었다.** 봉수대 단독, 혼천의 단독, 로컬 탐지 제한 단독은 화면에서 구별되는 효과가 없다. 더 쪼개려면 "혼천의만으로도 공유"같은 규칙 변경이 필요하다.
- **11단계(캐릭터)의 위치는 비어 있다.** CORE_LOOP 도식에서는 2~3단계 사이(유도·포박·압축)에 있지만 설계가 없다. 설계가 생기면 WP-009/010보다 앞에 둘지 GPT가 정한다.

## 사용법

```bash
# 테스트 모드 실행 (N = 1..8 또는 flow / jangseung / hwacha / network / waves / collapse / loop / build)
godot --path . --rendering-driver opengl3 -- --stage=3
```

- 화면 위 가운데 패널: 단계 번호·제목·출처 WP, 추가된 것, 해 볼 것, 이 단계의 효과를 보여 주는 실시간 수치.
- `[` / `]` (또는 PageUp / PageDown): 이전·다음 단계로 그 자리에서 전환. 새 런으로 시작하며 이전 단계의 시설·눌린 입력은 남지 않는다. 시작·결과 화면 위에서도 된다.
- 단계에 없는 명령(예: 2단계의 `2` 화차)은 거절되고 어느 단계에서 추가되는지 알려 준다. HUD의 조작 줄은 그 단계의 명령만 보여 준다.
- 1~6단계는 바로 시작한다(시작·결과 화면 없음). 7·8단계는 실제 메뉴 흐름이다.
- `--set key=value` 중 모드가 아닌 값(시드 등)은 단계 전환 뒤에도 유지된다. 모드 값(fixture, run_mode, outer_hp 등)은 단계가 정한다.

```bash
# 테스트 + 단계별 확인 + release export + 단계 순회 캡처 (greybox/sample × 1080p/720p)
.\scripts\verify_stages.ps1
```

```bash
# 단계별 확인 수치만 (헤드리스)
godot --headless --path . --script res://game/tools/stage_report.gd -- --out=D:/abs/path/stage_report.json
```

## 평가에 쓰는 방법

테스트 모드는 [게임 평가 지침](GAME_EVALUATION_GUIDE.md)의 체감 평가를 한 요인씩 하기 위한 도구다. 테스트가 통과했다고 재미가 검증된 것은 아니다. 단계별로 먼저 볼 항목은 다음과 같고, 현재 모두 **미평가**다.

| 단계 | 먼저 볼 평가 항목 |
|---|---|
| 1 | E-09 군집·길 가독성 |
| 2 | E-01 배치 → 흐름 변화의 인과, E-08 거절 피드백 |
| 3 | E-01 유도 → 압축 → 섬멸, E-04 장승·화차 역할 구분, E-08 사격 결과 |
| 4 | E-04 봉수·혼천의의 역할, E-02 끊기는 위험의 예측 가능성 |
| 5 | E-06 첫 3분 템포, E-02 외곽 압박 |
| 6 | E-02 붕괴의 위험·보상, E-03 회복 가능성 |
| 7 | E-06 재시작 속도, 결과 장부의 이해 |
| 8 | E-05 보상 → 다음 구매, E-02 투자 선택 |
