# 그래픽 제작·적용 가이드

작성일: 2026-09-20. WP-005의 제작 기준. 완성 이미지·에셋 승인을 뜻하지 않는다.

## 목표와 기준

작은 적이 골목으로 몰리고, 화차가 밀집 구역을 공격하며, 봉수 연결과 외곽 붕괴가 화면에서 읽히는 조선 사이버펑크 탑다운 픽셀아트다. 배경보다 전투·배치 판단을 우선한다.

사용자가 제공한 마을 게임 화면의 작은 스프라이트, 낮은 채도, 도로와 건물의 구분을 표현 방향으로 참고한다. 해당 게임의 이미지·아이콘·텍스처를 추출하거나 재사용하지 않는다. 기존 콘셉트/목업은 분위기 자료로 보존하며 실제 화면·게임용 에셋과 구분한다. 충돌 시 현재 게임 규칙과 이 가이드가 제작 기준이다.

## 시각 규칙

- 시점: 기존 고정 탑다운. 건물 앞면을 조금 보여주되 원근·카메라 변경으로 맵을 다시 만들지 않는다.
- 배경: 흙길·석재·목재·기와를 낮은 채도로 표현. 이동 가능한 길의 가장자리를 명확히 한다.
- 시설: 화차의 발사대, 장승의 얼굴/기둥, 봉수대의 등화, 혼천의의 고리로 실루엣을 구분한다.
- 색 의미: 청록=연결/관측, 주황=화차/발사, 적갈색·붉은색=적/위협. 단색 변화만으로 상태를 전달하지 않는다.
- 사이버펑크: 시설 동력부·연결 문양에 제한된 발광을 사용한다. 전장 전체 발광·안개로 적을 가리지 않는다.
- 그림자: 한 방향으로 통일하고 짧게 처리한다. 그림자와 지붕은 충돌·점유 정보가 아니다.
- 한글: 기존 UI의 가독성을 유지한다. 작은 픽셀 글꼴 교체는 이번 샘플에 포함하지 않는다.

## 크기·좌표·출력

게임 좌표는 1920×1080, 96×54셀, 셀 20px다. 지형 타일은 20×20px, 시설 바닥 점유는 40×40px(2×2셀)를 기준으로 한다. 그림 크기에 맞춰 셀 크기·충돌·경로를 바꾸지 않는다.

시설 기본 캔버스는 40×40px이며 바닥 중심을 기준점으로 삼는다. 상단 돌출이 필요한 경우 투명 여백과 기준점 오프셋을 명시한다. 주변 길·적·배치 테두리를 가리면 크기/배치를 수정한다. 기본 적 시안은 12×16px 캔버스 안에 제작하되 현재 약 9px 적 표시에 비해 밀집 가독성이 나빠지는지 확인하고 샘플에서 최종 크기를 고정한다. 적의 몸통 하단 중심을 기준점으로 하며 방향 전환 시 위치가 튀지 않아야 한다.

투명 RGBA PNG, 가장자리 번짐 없는 nearest 필터, 일정한 픽셀 밀도를 사용한다. 아틀라스 간 여백은 최소 2px로 하고 원본 개별 PNG를 보존한다. 논리 1080p 화면을 720p로 축소하면 비정수 배율이 되므로 모든 해상도에서 픽셀이 동일 크기라는 보장은 하지 않는다. 기존 화면 설정을 유지하고 실제 두 해상도에서 흐림·반짝임·실루엣 손실을 검사한다.

배경 → 건물/시설 → 적 → 짧은 전투 효과 → 선택/배치/경고 → 메뉴 순으로 시각 우선순위를 둔다. 정렬 방식은 Claude가 결정하되 도로·적을 지붕이 가리는 결과는 허용하지 않는다. 1,000개체를 각자 무거운 노드로 바꾸지 않고 기존 일괄 렌더링을 우선 유지한다.

## 상태 표현 계약

| 대상 | 표현 | 유지할 게임 의미 |
|---|---|---|
| 화차 | 기본/발사 프레임, 비활성은 소등·발사 정지 | 통행 비차단, 사거리·피해·쿨다운 불변 |
| 장승 | 얼굴/기둥과 바닥 표시, 비활성도 몸체 유지 | 통행 차단 유지, 붕괴 후 임의 제거 금지 |
| 봉수대 | 연결 시 점등/문양, 단절 시 소등+끊긴 연결 표시 | 실제 그룹·간선 상태만 반영 |
| 혼천의 | 고리 형태, 작동/소등 표현 | 실제 관측 상태를 읽음, 새 탐지 기능 없음 |
| 거점 | 정상/피격/붕괴 구분 | 외곽 붕괴와 핵심 패배의 의미 구분 |
| 회수 화차 | 기존 자리의 몸체 제거, 회수 대기 표시, 배치 시 몸체 복귀 | 한 개체의 회수/재배치, 시설 복제 금지 |
| 배치 | 가능 테두리+체크 / 불가 테두리+금지 표시 | 현 프레임 점유·지형·내곽 검사 결과 그대로 사용 |

전투 효과는 실제 발사·피해 이벤트에 연결한다. 사격이 없는데 효과만 반복하거나, 렌더 프레임마다 같은 발사 이벤트를 새 효과로 중복 생성하지 않는다. 일시정지에서는 전투 애니메이션도 멈추고 재시작 시 이전 효과를 비운다. 과도한 광원·입자·화면 흔들림은 추가하지 않는다.

## 제작과 역할

| 담당 | 책임 | 인수 산출물 |
|---|---|---|
| GPT | 시각 명세·리소스 목록·제작 지시·리뷰 | 이 가이드, WP, 수정 요청/PASS |
| 이미지 생성 도구 | GPT 지시에 따른 원본 시안 생성 | 생성 원본과 작업 기록; 자동으로 게임용 완성본으로 간주하지 않음 |
| GPT + Claude | GPT는 보정 기준·눈검수, Claude는 실행 가능한 자동 보정·파일 정리 | 투명 배경·기준점·프레임 크기를 검증한 리소스 |
| Claude Code | 가져오기·아틀라스·렌더 적용·테스트·빌드·증거 | 플레이 가능한 샘플과 결과 문서 |
| 사용자 | 실제 샘플의 스타일 방향 확인, 전체 완성 화면 확인 | 확인 날짜·화면 버전·수정 의견 |

별도 픽셀 편집 인력은 배정된 상태가 아니다. 자동 보정으로 해결되지 않는 실루엣/프레임 문제는 GPT가 재제작 지시를 작성하고 재생성·검수한다. 해결되지 않으면 해당 리소스를 미완료로 기록한다. Claude가 이미지 생성 도구에 접근할 수 없으면 필요한 asset ID와 규격을 명시해 GPT 제작 단계로 넘기며 제작 완료를 주장하지 않는다. 일상적인 가져오기·파일 정리에는 반복 승인을 요구하지 않는다.

## 파일과 추적

- `docs/art/source/`: 선택된 제작 원본·제작 지시 기록. 대형 중간 시안 전체를 저장하지 않는다.
- `assets/art/wp005/`: 검수된 게임용 PNG/아틀라스. 런타임에 필요한 것만 포함한다.
- `docs/art/ASSET_MANIFEST.csv`: ID·규격·기준점·프레임·출처·권리·상태·적용 경로·해시.
- `results/evidence/wp-005/`: 실제 실행 캡처·전투 상태 비교·테스트·성능 JSON. 콘셉트 이미지를 실행 증거로 사용하지 않는다.

파일명은 `<asset_id>_<state>_v01.png`로 시작하고 수정본은 버전을 올린다. 원본 보존, 런타임 참조 교체, 미사용 파일 정리는 별도 구분한다. 외부 폰트/텍스처를 추가하면 라이선스 파일을 함께 남긴다. 생성 도구 이름·제작일·제작 지시/작업 식별자를 기록하며 생성물이라는 이유만으로 권리를 단정하지 않는다.
