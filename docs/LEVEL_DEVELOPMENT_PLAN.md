# 레벨 디자인 개발 계획

2026-09-28 · 계획 작성 / 구현 미착수

## 목표와 범위

**에디터에서 만든 지도를 실제 전투로 실행하고, 배치 선택의 결과를 확인할 수 있는 Stage001~004를 순차 제작한다.** 지도 검사와 동선 미리보기만으로 게임플레이 완료를 판정하지 않는다.

기준: [레벨 규칙](LEVEL_DESIGN_RULES.md), [단계별 설계](LEVEL_DESIGN_STAGES.md), [재구축 계획](DESIGN_VALIDATION_REBUILD_PLAN.md), [개발 10계명](DEVELOPMENT_TEN_PRINCIPLES.md). 기존 WP 상태와 승인 이력은 유지한다. 아래 LD-DEV 번호는 개발 계획 내부 작업 ID이며 새 WP 번호나 READY 선언이 아니다.

현재 로컬에는 미커밋 맵 에디터·테스트 변경이 있다. 시작 시 작업 소유와 기준 SHA/변경 파일을 기록하고 보존한다. WP008 등 다른 브랜치 구현은 실제 SHA·결과 확인 뒤 재사용하며, 문서의 과거 착수 지시만 보고 다시 구현하지 않는다.

## 2. 첫 개발 묶음 — 지도 신뢰성

대상 후보: `game/maps/stage_map_definition.gd`, `game/tools/map_editor.gd`, `tests/test_stage_map_editor.gd`, `tests/run_stage_map_tests.gd`. 기존 내용을 읽고 필요한 부분만 수정한다. 신규 fixture 저장 위치는 기존 로딩 방식을 확인한 뒤 정하고 결과에 기록한다.

제외: 성문 HP, 공성 적, 장승 파괴, 새 경제, 전체 아트 교체, 전투 밸런스 변경. 기존 테스트 기대값을 실패에 맞춰 낮추지 않는다. 새 음성 시험은 현행 R-02를 재현하는지 먼저 확인한다.

## 3. 두 번째 개발 묶음 — 지도에서 실제 전투로

### 데이터와 책임

- 지도에는 지형·성벽·진입·성문·목표·생성 범위를 둔다. 적 체력/속도·공격·승패·웨이브 편성·사용 시설은 명시적 전투 프로필로 연결한다.
- 현재 확인한 map tuning의 wave_count/spawn_rate/test_duration만으로 적 총량·사격 규칙·승패까지 정의됐다고 간주하지 않는다. 필요한 필드와 기본값·버전 변환은 최소 범위로 추가한다.
- core는 경로·전투·설치 판정을 담당하고 scene은 표시와 명령 전달을 담당한다. 에디터의 이동 점 애니메이션을 전투 로직으로 재사용하지 않는다.
- 조사 대상은 `game/core/battle.gd`, `terrain_grid.gd`, `path_network.gd`, `placement.gd`, `wave_director.gd`, `game/scenes/main.gd`. 이는 수정 확정 목록이 아니며 기존 구조 확인 후 변경 범위를 정한다.

### 통합 완료 기준

1. 지정한 stage_id/파일로 진입했을 때 화면과 core의 벽·문·목표·생성 좌표가 일치한다. 오류 파일은 이유를 표시하고 정상 맵으로 조용히 대체하지 않는다.
2. 맵 위 화차가 유효 타깃 존의 적에게 실제 발사하고 피해·처치가 발생한다. 사거리 원만 겹치는 상태로 통과하지 않는다. 기존 WP001/002 존 fixture는 보존한다.
3. 목표 피해와 승패는 선택한 기존 프로필과 일치한다. 새로운 성문 지속 공격 규칙이나 궁성 방어 결정을 암묵적으로 도입하지 않는다. 기존 프로필로 표현 불가능한 항목은 차이표와 별도 결정 요청으로 남긴다.
4. 준비→전투→결과→재시작이 한 맵에서 이어진다. 재시작 시 적·시설·물자·웨이브·타이머·망·이전 런 이벤트가 초기화된다. 동일 seed 재도전과 새 seed 실행을 구분한다.
5. 지도 파일/프로필/seed/빌드와 입력·첫 사격·처치·목표 피해·종료 이벤트를 증거에 연결한다. 실제 전투 통합 전후 회귀를 실행한다.

## 4. 단계별 콘텐츠 제작 작업

Stage001: 무료 배치 실험에서 화차 1기·적 1종을 고정하고 유효/비유효 배치를 비교한다. 이 실험 프로필을 캠페인 초기 자산에 덮어쓰지 않는다. 10초 안에 성문/목표를 식별하는지 실제 관찰한다.

Stage002: 생성률만 바꾼 비교 실행을 먼저 만든다. 적 총수와 능력·시설·지형·seed는 고정한다. 웨이브별 예정/실제 생성 시각을 남겨 압박 변화가 실행됐는지 확인한다.

Stage003: 경로 검사를 통과한 수정안을 사용한다. 같은 화차/예산의 전방/성문 배치에서 적 노출·발사·피해를 비교한다. 미리보기 좌표가 달라진 것만으로 경험 통과를 선언하지 않는다.

Stage004: 장승 없음→A→B의 세 조건을 같은 설정으로 실행한다. 설치 거절·포화 골목 규칙·화차 통행 비차단을 유지한다. 장승 배치의 동선 효과와 고정 지형 효과를 분리한다.

각 레벨은 테스트용 설정과 플레이용 데이터의 차이를 기록한다. 레벨에 고유한 편법을 core에 하드코딩하지 않는다. 좌표 후보가 실제 설치·타기팅 검사에 실패하면 원인과 수정안을 보고한다.

| 레벨 | 다음 확인 | 개발 범위가 열리는 조건 |
|---|---|---|

| Stage006 연결 | 공유 시야가 만든 실제 사격, 동비용 직접 화력 대안 | 연결 역할 채택 및 비교 조건 확정. 효과 없으면 후보 보류 |
| Stage007 성문 공방 | WP009 계약·성문 HP·적 공격 상태 | 지키는 성공과 돌파 후 수습 모두 성립. 강제 붕괴 없음 |

미정 범위: 도시 구역 확보, 메타 성장, 무작위 합성, 신규 장승 능력, 보스, 캠페인 해금. 이번 계획의 작업량·일정에 포함하지 않는다.

## 6. 역할·제출·판정

- GPT: 행동 목표·기획 차이·AC를 고정하고 증거에 따라 PASS/REVISE 판단. 사용자에게 필요한 결정은 구체적인 충돌/선택 단위로 제시.
- Claude Code: 기존 변경 보존, 구현/테스트/실행/수정, 근거와 미실행 범위 제출. 이번 계획 작성은 Claude 실행 요청 전송이나 개발 착수를 뜻하지 않음.
- 사용자: 정상 속도 플레이에서 목표 이해·배치 선택·실패 원인을 확인. 자동 시험으로 사용자 평가를 대신하지 않음.

묶음별 결과는 `results/LD-DEV-XX-RESULT.md`, 증거는 `results/evidence/level-development/LD-DEV-XX/<실행ID>/`에 새로 저장하는 안을 사용한다. 기준/구현 SHA, dirty 변경 목록, 파일/설정 해시, 환경, 실행 방법, AC별 PASS/FAIL/NOT RUN, 관찰 사실→영향→수정→재검증, 이미지/영상 경로를 포함한다. 영상은 에디터 미리보기와 실제 전투를 제목부터 구분한다.

검증은 관련 단위 시험→해당 묶음 통합→실제 화면/영상→영향 범위 회귀 순서다. 성능에 영향이 있는 경로/전투/망 변경은 기존 1,000체 성능 계약을 재측정하고 raw frame/alive와 유지 부하를 제출한다. 문서 작성만 한 이번 턴에는 게임 테스트를 실행하지 않는다.

필수 AC 미완이면 IN_PROGRESS, 증거 제출 뒤 REVIEW, GPT PASS 뒤 완료로 기록한다. 일정은 LD-DEV-01 결과와 LD-DEV-02 통합 조사 뒤 산정하며 현재 임의 날짜를 약속하지 않는다.
