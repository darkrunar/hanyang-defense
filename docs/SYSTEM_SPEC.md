## WP-001: 흐름과 화력

- 테스트 맵은 세 진입로와 공통 방어 목표를 갖는다. 경로에 식별자를 부여한다.
- 적은 유효한 경로로 이동한다. 배치·제거가 경로 버전을 바꾸면 영향을 받는 적이 갱신된 통행 상태를 반영한다.
- 초기 정책: 어느 진입점이든 목표까지 가는 모든 길을 막는 배치는 거절한다. 실패 시 통행 상태와 배치 상태 모두 원상 유지한다.
- 이미 적이 점유한 위치에는 장승을 놓을 수 없다. 파괴·제거 후 경로가 다시 열려야 한다.
- 밀도는 설정된 원형 반경 안의 생존 적 수로 정의한다. 경계 위의 적도 포함한다.
- 화차는 사거리 안의 후보 영역 중 적 수가 가장 많은 영역을 겨냥한다. 동률이면 안정된 후보 ID 순서로 선택한다. 적이 없으면 발사하지 않는다.
- 피해는 범위 안의 생존 적에 한 번만 적용하고, 사망 처리는 한 번만 집계한다.
- 생성 누계와 동시 생존 수를 구분한다. 1,000개체 테스트는 처치를 끈 구간에서 동시 생존 수를 먼저 입증한다.

## WP-002: 연결에 따른 행동 변화

- 활성 봉수대와 연결 범위 안의 시설을 그래프로 표현한다. 파괴·제거·비활성 전환 시 연결을 갱신한다.
- 프로토타입에서는 화차의 로컬 탐지 범위보다 사격 범위를 넓게 둔다. 봉수망은 같은 연결 그룹의 센서가 감지한 표적을 전달한다.
- 연결된 화차는 공유 표적이 자신의 사격 범위 안이면 공격할 수 있다. 연결 해제 시 로컬 탐지로 복귀한다. 무한 사거리는 부여하지 않는다.
- 센서가 사라지거나 적이 죽은 경우 오래된 표적을 폐기한다. 동일 적을 여러 센서가 감지해도 밀도 계산에서 중복 집계하지 않는다.
- 연결 그래프에 순환이 있어도 이벤트가 무한 전파되지 않는다. 다른 연결 그룹으로 정보가 새지 않는다.

## WP-003: 검증과 후퇴

- 외곽·내곽 두 구역, 외곽 거점과 최종 핵심 시설을 둔다.
- 외곽 거점 HP가 0이 되면 붕괴를 한 번 발생시키고 외곽 시설을 비활성화한다. 살아 있는 적의 목표를 내곽으로 갱신한다.
- 검증용 초기 규칙: 후퇴 시 지정된 화차 1대만 내곽에 무료 재배치한다. 실제 회수 비용·경제는 후속 명세로 분리한다.
- 모든 웨이브 생성 종료와 남은 적 0, 핵심 시설 생존이 승리 조건이다. 핵심 HP 0은 즉시 패배이며 동시 조건에서는 패배를 우선한다.
- 런 종료 이후 새 생성·피해·보상을 중단한다. 재시작하면 적·연결·구역·점수를 초기화한다.

## 데이터와 관측

적, 시설, 경로, 구역, 웨이브는 안정된 ID를 갖는다. 위치·HP·활성 상태·목표 ID와 시드, 경로 버전, 연결 그룹을 관측할 수 있어야 한다. 디버그 오버레이에는 생존 수, 경로, 밀도, 선택 표적, 연결 상태, 누수 수를 필요한 WP에서만 표시한다.

## 성능 검증 계약

WP-001 착수 시 엔진·버전, 대상 플랫폼, 기준 장비와 합격 예산을 DECISIONS에 기록한다. 잠정 제안은 1080p 독립 실행 빌드에서 동시 1,000개체, 준비 10초 후 60초 측정, 평균 60 FPS 이상과 p95 프레임 시간 25ms 이하이다. 이 값은 확정 성능 요구가 아니므로 착수 시 채택 또는 대안을 명시해야 한다.

생성·이동만의 성능과 화차·피해·경로 변경이 활성화된 성능을 각각 기록한다. 충돌·막힘·메모리 증가도 함께 확인한다. 측정 환경이 없으면 NOT RUN이며 성능 기준은 통과하지 않은 것이다. 5,000개체는 이후 확장 조사다.
