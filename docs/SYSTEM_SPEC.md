## WP-001: 흐름과 화력

- 테스트 맵은 세 진입로와 공통 방어 목표를 갖는다. 경로에 식별자를 부여한다.
- 적은 유효한 경로로 이동한다. 배치·제거가 경로 버전을 바꾸면 영향을 받는 적이 갱신된 통행 상태를 반영한다.
- 초기 정책: 어느 진입점이든 목표까지 가는 모든 길을 막는 배치는 거절한다. 실패 시 통행 상태와 배치 상태 모두 원상 유지한다.
- 이미 적이 점유한 위치에는 장승을 놓을 수 없다. 파괴·제거 후 경로가 다시 열려야 한다.
- 시설은 2×2 셀을 점유하며 다른 시설과 겹칠 수 없다. 통행 차단은 장승만 한다. 화차의 점유는 시설 중복 배치를 막을 뿐 적의 통행을 막지 않으며, 적은 화차 footprint를 그대로 통과한다 (DECISIONS D-011, GPT WP-001 한정 승인. 봉수대 등 다른 시설의 통행 규칙은 별도 결정).
- 점유 판정은 적의 현재 좌표를 기준으로 한다. 이동 스텝이 끝난 시점의 위치와 배치 검증이 보는 위치가 항상 같아야 하며, 시각 오버레이의 가능/불가능 표시도 같은 판정을 쓴다.
- 밀도는 설정된 원형 반경 안의 생존 적 수로 정의한다. 경계 위의 적도 포함한다.
- 화차는 사거리 안의 후보 영역 중 적 수가 가장 많은 영역을 겨냥한다. 동률이면 안정된 후보 ID 순서로 선택한다. 적이 없으면 발사하지 않는다.
- 피해는 범위 안의 생존 적에 한 번만 적용하고, 사망 처리는 한 번만 집계한다.
- 생성 누계와 동시 생존 수를 구분한다. 1,000개체 테스트는 처치를 끈 구간에서 동시 생존 수를 먼저 입증한다.

## WP-002: 연결에 따른 행동 변화 (READY, 2026-09-14)

확정 상세 계약·초기값·고정 fixture·AC-01~08은 [WP-002](../backlog/WP-002.md), 기획 결정은 DECISIONS D-012~015를 따른다. 이 절의 규칙은 초기 제안을 구체화한 구현 기준이다.

- 활성 봉수대만 중계한다. 중심 거리 180px 이하의 무방향 그래프를 구성하며 센서/화차는 범위 내 최근접 봉수대 하나에만 부착한다(동률 시설 ID). 단말 간 직접 연결·중계는 없다.
- 센서 탐지 140px, 화차 로컬 탐지 100px, 사거리 200px. 탐지는 현재 적 좌표, 사거리는 후보 영역 중심 기준이며 경계를 포함한다. 시야 차폐·통신 지연은 없다.
- 각 화차는 로컬 적 ID와 같은 그룹 센서의 적 ID 합집합으로 후보 영역 밀도를 계산한다. 중복 센서·순환망·로컬 중복을 제거한다. 부분 관측에서 전역 밀도를 노출하지 않는다. 최고 밀도/영역 ID 동률 규칙과 광역 피해는 WP-001을 유지한다.
- 시설 변경과 이동을 처리한 틱의 사격 전에 연결·탐지를 갱신한다. 단절·사망·센서 소멸/범위 이탈 후 마지막 탐지 출처가 없으면 즉시 폐기한다. 다른 출처가 남으면 유지한다. 연결 변화로 쿨다운을 초기화하지 않는다.
- 봉수대·센서는 2×2 점유지만 적 통행을 막지 않는다. 기존 현재 적 점유·중복·지형·경계 배치 검증을 사용한다. 비활성은 점유를 유지하고 기능만 중단, 제거는 점유도 해제한다. 시설 HP/공격 시스템은 범위 밖이다.
- WP-001 검증 모드는 기존 규칙을 보존하고 WP-002 모드는 로컬 탐지 제한을 적용한다. 새 모드의 행동 차이를 회귀 실패로 혼동하지 않으며 모드를 결과에 명시한다.
- 기본 16시설(화차4/봉수대8/센서4)의 고정 배치에서 네트워크 이동/전투를 각각 측정한다. 전투는 연결 전환12회와 장승 경로 변경12회, 실제 공유 사격을 포함한다. D-009 예산과 매 프레임 1000체 유지·원시 프레임/생존 배열 검산을 필수로 한다.

## WP-003: 검증과 후퇴 (DRAFT)

기존 최소 기준은 아래와 같다. 2026-09-15에 상세 [WP-003 초안](../backlog/WP-003.md)을 정리했다. 구역/도달 처리·회수 상태·웨이브 수치·검증 배치의 세부안은 DECISIONS P-012~016의 미채택 제안이며, READY 전 검토 후 이 명세에 확정 규칙으로 반영한다.

- 외곽·내곽 두 구역, 외곽 거점과 최종 핵심 시설을 둔다.
- 외곽 거점 HP가 0이 되면 붕괴를 한 번 발생시키고 외곽 시설을 비활성화한다. 살아 있는 적의 목표를 내곽으로 갱신한다.
- 검증용 초기 규칙: 후퇴 시 지정된 화차 1대만 내곽에 무료 재배치한다. 실제 회수 비용·경제는 후속 명세로 분리한다.
- 모든 웨이브 생성 종료와 남은 적 0, 핵심 시설 생존이 승리 조건이다. 핵심 HP 0은 즉시 패배이며 동시 조건에서는 패배를 우선한다.
- 런 종료 이후 새 생성·피해·보상을 중단한다. 재시작하면 적·연결·구역·점수를 초기화한다.

WP-003 초안 이후 정책 일부는 D-019~021로 채택했다: 전용10존(기존8+Z8/Z9), 중영 화차 회수 대상, 핵심HP 버퍼 및 F3 붕괴+5초 비교 시점. 상세 좌표·판단은 WP-003의 「결정 요청 후속 판단」을 따른다. 전체 fixture 검증과 READY 전환은 아직 완료되지 않았다.

## 데이터와 관측

적, 시설, 경로, 구역, 웨이브는 안정된 ID를 갖는다. 위치·HP·활성 상태·목표 ID와 시드, 경로 버전, 연결 그룹을 관측할 수 있어야 한다. 디버그 오버레이에는 생존 수, 경로, 밀도, 선택 표적, 연결 상태, 누수 수를 필요한 WP에서만 표시한다.

## 성능 검증 계약

D-009에서 채택한 예산은 1080p 독립 릴리스 빌드, 동시 생존 1,000개체, 준비 10초 후 60초 측정, 평균 60 FPS 이상과 p95 프레임 시간 25ms 이하이다. WP-002에도 적용하며 고정 시설·이벤트 부하는 해당 WP를 따른다. 매 프레임 alive≥1000을 원시 생존 배열로 증명하고 FPS·p95를 원시 프레임 배열로 검산한다.

생성·이동만의 성능과 화차·피해·경로 변경이 활성화된 성능을 각각 기록한다. 충돌·막힘·메모리 증가도 함께 확인한다. 측정 환경이 없으면 NOT RUN이며 성능 기준은 통과하지 않은 것이다. 5,000개체는 이후 확장 조사다.
