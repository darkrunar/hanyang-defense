# 기획 검증 재구축 계획

2026-09-23 · 계획 작성 완료 / 기본 규칙 합의 전 / 실험 미실행

## 목적과 기준

공격과 방어의 기본 규칙부터 사용자와 합의하고, 작은 전투에서 시작해 경제·연결·재편·도시 확장으로 검증 범위를 넓힌다. 기능 수가 늘어나는 것과 플레이어의 선택이 확장되는 것을 구분한다.

검토 기준은 로컬 `wp/005-art-sample`의 `daef43a`. 이는 기획 문서 기준이며 다른 구현 브랜치/PR의 최신 상태를 재검증한 결과가 아니다. 기존 승인 기록·코드·에셋·증거는 재사용 자산으로 보존한다. 이번 계획은 게임 규칙 변경이나 WP-009/010의 READY 승격을 뜻하지 않는다.

사용자는 공격·방어부터 기획을 정리하는 질문 진행을 요청했다. ‘배치를 잘 짜서 많은 적을 막았다’는 선호 맥락으로 참고하되 최종 방어 대상·공격 방식·직접 조작 방식은 이번 재정의에서 아직 답변되지 않았다. GPT가 제안한 궁성 방어 또는 도달 후 지속 공격을 채택된 규칙으로 취급하지 않는다.

기준 문서: [개발 10계명](DEVELOPMENT_TEN_PRINCIPLES.md), [게임 평가 지침](GAME_EVALUATION_GUIDE.md), [기존 코어루프](CORE_LOOP.md), [기존 확장 계획](GAMEPLAY_EXPANSION_PLAN.md).

## 1. 질문으로 기본 규칙 합의

대화에서는 핵심 질문 하나씩 진행한다. 현재 질문에 답하면 합의 내용·남은 모호함을 짧게 되짚고 다음 질문으로 넘어간다. 아래 목록을 한 번에 설문으로 요구하지 않는다. 답변 없는 항목은 미정으로 유지한다.

| 순서 | 사용자에게 확인할 질문 | 확정할 규칙 |
|---|---|---|
| Q1 방어 대상 | 끝까지 지켜야 하는 것은 무엇이며, 무엇을 잃으면 패배하는가? | 최종 방어 대상 / 중간 손실 / 패배 조건의 구분 |
| Q2 적의 공격 | 적은 무엇을 목표로 이동하며, 도달하면 어떤 행동을 하는가? | 목표 선택, 도달 시 소멸·피해 또는 지속 공격, 경로상 시설 공격 여부 |
| Q3 플레이어의 방어 | 플레이어는 무엇을 직접 조작해 적을 막는가? | 시설 배치·표적 지시·캐릭터 조작의 범위, 자동 공격과 수동 행동 구분 |
| Q4 공격과 저지 | 적을 죽이는 수단과 이동을 막거나 늦추는 수단은 무엇인가? | 사거리·타깃·피해·차단·우회·장애물 파괴의 역할과 상호작용 |
| Q5 전투의 끝 | 어떤 조건까지 버티거나 어떤 적을 없애면 승리하는가? | 웨이브·시간·보스 등 종료 조건, 진행 중 수습 가능성 |
| Q6 획득과 소비 | 방어 성공으로 무엇을 얻고, 다음 공격 전에 무엇을 바꾸는가? | 보상 시점·소비 선택·비축의 의미·준비 시간 |
| Q7 성공과 실패 이후 | 잘 막았을 때와 뚫렸을 때 각각 어떤 선택이 열리는가? | 전선 유지·확장과 손실·후퇴·재건의 분기 |
| Q8 반복 | 다음 판은 무엇이 같고 무엇이 달라지는가? | 동일 조건 재도전, 랜덤 변주, 해금의 범위 |

Q1~Q5 답변을 한 장의 전투 규칙표로 정리한다. ‘적 등장 → 목표로 이동 → 방어 수단과 교전 → 처치 또는 목표 피해 → 승패’의 각 화살표에 조건과 결과를 적는다. 시설·장르 명칭만으로 빈칸을 대신하지 않는다. 대상 플레이어의 숙련도와 기대 경험도 합의된 조작 구조를 바탕으로 적는다.

## 2. 단계별 검증

아래 단계는 새 WP 번호나 구현 완료 상태가 아니다. 각 실험 전에 가설·조건·관측 항목·통과 기준을 고정하고 필요한 구현 변경만 별도 WP로 명세한다. 단계마다 직전 단계의 핵심 행동이 유지되는지도 확인한다.

| 단계 | 검증 질문 / 최소 실험 | 관측과 통과 조건 | 다음 단계에 넘길 것 |
|---|---|---|---|
| V0 기본 전투 | Q1~Q5 합의 후 적 1종·방어 수단 1종·방어 대상 1종의 최소 장면 | 합의한 이동·공격·처치·목표 피해·승패 경계가 일치. 정상 속도에서 무엇을 지키고 어떻게 피해를 막는지 설명 가능 | 완결된 공격·방어 규칙 |
| V1 배치의 의미 | 적 편성과 총비용을 고정하고 배치만 변경. 장승 등은 합의된 경우 도입 | 이동 경로·집결·사격·누수 변화 기록. 차이의 원인을 플레이어가 설명할 수 있음. 원인 없이 수치만 오른 경우 보완 | 배치가 결과를 바꾸는 최소 전투 |
| V2 보상·증설 | Q6 합의 후 최소 2회 공격 주기로 획득→소비→다음 방어 비교 | 보상 이전/이후 잔액과 구매 가능 시점, 실제 지출·비축 이유, 다음 전투 변화. 최종 보상의 사용처도 명시. 무건설 승리를 자동 실패로 판정하지 않음 | 전투가 다음 선택의 자원을 만드는 순환 |
| V3 연결의 가치 | 직결 화력 투자와 봉수·관측 투자 비교. 총비용과 적 조건 통제 | 공유 표적 사격과 방어 결과, 연결을 이해하는지 관찰. 연결이 유리한 상황과 직접 화력이 유리한 상황을 각각 확인 | 단일 시설에서 시설 조합으로 확장 |
| V4 위협·재편 | 성문/공성 규칙 채택 시 역할을 하나씩 추가. 방어 성공·돌파 후 수습·최종 패배 비교 | 예고를 보고 합법적인 대응 가능. 자연 붕괴와 강제 시험을 구분. 상한까지 외곽 투자 후에도 합의한 복구 행동이 가능한지 확인. 모든 분기에서 결과가 규칙과 일치 | 유지와 후퇴 중 선택할 수 있는 방어선 |
| V5 구역 확장 | Q7 합의 후 인접 구역 하나만 대상으로 확보/비확보 비교 | 확보 조건·비용·새 이점·새 위협 명확. 새 배치/관측/전선 선택이 실제로 추가되고 기존 거점 방어와 연결됨. 맵 또는 적 수 증가만으로 통과하지 않음 | 구역 간 연결과 다중 전선의 작은 사례 |
| V6 런 반복 | Q8 합의 후 동일 조건 재도전과 채택한 변주를 구분하여 시험 | 지난 판에서 배운 전략을 수정할 수 있는지, 변주가 다른 선택을 만드는지 기록. 해금을 선택하지 않았다면 메타 성장 구현 불필요 | 한 판의 학습과 다음 판의 동기 |

처음부터 1,000체로 모든 가설을 검증하지 않는다. 작은 장면에서 규칙과 인과를 확인한 뒤 채택한 기능이 대량 전투에서도 읽히고 작동하는지 확대한다. 기존 WP의 1,000체 성능 계약은 해당 변경의 회귀/통합 검증에서 유지한다.

## 4. 기록·판정과 반복 방식

각 실험은 다음 양식으로 기록한다.

- 질문 ID / 가설 / 관련 T-ID·E-ID / 합의된 규칙과 미정 항목
- 기준·구현 SHA / 빌드 해시 / 설정·seed / 실행 명령·해상도
- A/B의 유일한 변경점과 통제 조건. 여러 요인을 바꿨다면 해당 제한을 명시
- 자동 검증과 정상 속도 실제 플레이 관찰을 구분. 참가자 수·경험·힌트 제공 여부·실행 방식 기록
- 입력·배치·획득·소비·피해·연결·승패의 시간 기록, 필요한 캡처·영상
- 관찰 사실 → 플레이어 영향 → 개선안 → 재검증 조건
- 기능: PASS / FAIL / NOT RUN. 경험: 충족 / 보완 필요 / 미평가 / 비해당
- 유지 / 수정 후 재실험 / 후보 보류 결정과 근거, 담당, 다음 한 가지 행동

수치 합격선은 실험 전에 정한다. 비교 관측 없이 임의의 재미 점수나 보편적 승률 목표를 만들지 않는다. 사용자 한 명의 관찰은 탐색 근거이며 전체 이용자의 재미가 검증됐다고 일반화하지 않는다. 조건을 달리한 시드·전략 검증은 최초 관측 이후 필요한 범위로 확대한다.

미통과 시 가장 작은 원인부터 수정해 같은 실험을 반복한다. 모든 단계를 한꺼번에 구현해 어떤 변화가 효과를 냈는지 알 수 없는 상태를 피한다. 기존 WP의 기술 PASS와 새 기획의 적합성 판정은 각각 보존한다.

## 5. 기존 작업과의 연결

- WP-001~004: 경로·사격·망·붕괴·재시작 코드와 증거를 재사용. 기존 DONE을 취소하거나 새 규칙에 대한 PASS로 전용하지 않는다.
- WP-008: 경제·건설 검증 자산 후보. 실제 사용 전 해당 구현 브랜치/PR의 SHA·결과를 확인한다. 현재 문서 브랜치의 READY 표기를 최신 구현 상태로 해석하거나 작업을 처음부터 다시 지시하지 않는다.
- WP-009/010: DRAFT 유지. Q1~Q5 및 관련 Q7 결정과 V0~V3 결과를 반영해 기존 선행 조건 충족 시 READY 명세 작성. 이번 계획으로 착수하지 않는다.
- WP-005: 현행 아트/가독성 보완과 증거는 유지. V0~V3는 기존 샘플로 검증 가능. WP-006 그래픽 범위 확대는 게임 규칙상 구역 확보와 구분한다.
- 랜덤 보급·합성, 추가 재화, 캐릭터 스킬, 메타 해금은 후보. 기본 질문의 답변 없이 구현 범위로 끌어오지 않는다.
- 규칙 채택 후 GPT가 DECISIONS·GAME_DESIGN·CORE_LOOP·SYSTEM_SPEC·관련 WP와 개발 요청의 영향 부분을 함께 갱신한다. 기존 상위 문서의 오래된 상태 표기는 브랜치별 증거를 확인한 뒤 정리한다.

## 6. 역할과 첫 실행 순서

1. GPT → Q1 하나를 제시하고 사용자 답변을 정리한다. 기본 대상/패배 조건을 먼저 묻고 도달 후 공격 방식은 Q2에서 다룬다.
2. 사용자 → 의도한 공격·방어 경험과 선택에 답한다. 미정이면 GPT가 소수 대안을 비교하고 잠정 가설임을 표시한다.
3. GPT → Q1~Q5 합의 후 기존 계약과 차이표 및 V0 실험 명세를 작성한다. Q6~Q8에 의존하지 않는 기초 검증 준비는 병행 가능하다.
4. Claude → 합의된 실험에 필요한 최소 구현·테스트·실행 증거를 제출한다. 일상적 기술 선택은 기존 계약대로 진행한다.
5. GPT → 증거와 사용자 체감 의견을 함께 리뷰하고 다음 실험으로 연결한다. 새 실험 준비는 가능하되 미검증 가설을 확정 규칙으로 누적하지 않는다.

첫 산출물은 **방어 대상·적의 공격·플레이어 조작·저지/처치·승패 조건을 담은 전투 규칙표와 V0 실험 명세**다. 이번 턴의 산출물은 본 계획이며 사용자 답변·규칙 확정·실험 실행 결과는 아직 없다.
