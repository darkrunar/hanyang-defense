# WP-005 게임샷 개선 실행 계획

2026-09-20 · 상태: PLANNED · 기준 구현: `fba8edd` · D-053

사용자의 게임샷 평가 반영 요청으로 추가한 계획이다. 구현·검증 완료나 사용자 스타일 승인을 의미하지 않는다. [WP-005](../../backlog/WP-005.md)의 기존 AC와 전투 계약을 유지한다.

## 목표

**시설 이름과 디버그 표시를 꺼도 어디를 지키고, 무엇이 작동하며, 어디에 회수 화차를 배치할 수 있는지 읽히는 광화문 앞 한 화면을 완성한다.**

참조 화면에서 취할 요소는 도시를 나누는 건물 실루엣·길·경계의 구성이다. 참조 게임의 이미지나 UI를 복제하지 않는다. 단색 공백을 줄이기 위해 새 지형·충돌·경로·카메라 체계를 추가하지 않는다.

## 우선순위와 역할

| 순서 | 작업 | 담당 | 완료 확인 |
|---|---|---|---|
| V-01 | 일반 플레이 기본값에서 상세 패널·밀도 존·사거리 원을 접는다. 웨이브·거점 HP·회수 여부·배치 안내를 우선 표시하고 시설명/그룹 수치 겹침을 해소한다. 기존 토글로 개발 정보 접근을 유지한다 | Claude 적용, GPT 검수 | 1080p/720p 기본 화면에서 핵심 안내가 읽히고 시설/HP 문구가 겹치지 않음. 토글·메뉴·재시작 입력 회귀 통과 |
| V-02 | 적 몸통 중간톤·외곽선과 시설 팔레트를 보정한다. 작은 크기에서 남는 실루엣을 우선하며 상태별 형태 차이를 유지한다 | GPT 제작/규격, Claude 적용 | 720p 실제 크기에서 어두운 길 위 적 군집과 이동 방향 식별. 라벨 없는 시설 4종 및 활성/단절/비활성 구분. 동일 상태의 외곽선 on/off 비교 |
| V-03 | 광화문 앞 샘플 안에서 성문·성벽·처마·용마루·짧은 접지 그림자로 건물 단위를 구분한다. 넓은 반복 기와 면을 건물 실루엣으로 나눈다 | GPT 제작, Claude 배치 | 전체 화면에서 길·건물·성곽을 구분하고 큰 반복 면이 완화됨. 근접 점유 오버레이에서 기존 통행/배치 영역과 정합 |
| V-04 | 봉수 연결의 청록 점등, 화차 발사/탄착의 주황, 붕괴 후 소등을 일관된 상태 표현으로 적용한다. 색 외에 형태·점등·사선 표시를 병용한다 | GPT 아트 방향, Claude 이벤트 연결 | 이름표 없이 작동/단절/비활성·회수 구분. 효과가 실제 이벤트에 1회 대응하고 정지·재시작 뒤 잔류 없음 |

V-01 → V-02 → V-03 → V-04 순으로 통합한다. 제작은 선행 규격이 확정된 항목부터 준비 가능. 기존 적 외곽선과 소등 표시는 재구현 완료로 계산하지 않고 실제 화면 개선 여부를 검증한다.

## 범위 경계

- WP-005: 기존 HUD의 기본 노출·문구 겹침·선택/호버 정보 정리, 기존 샘플 셀 x30..65/y6..30의 건축 실루엣, 적/시설 대비, 이미 계약된 발사·점등·붕괴 표현.
- WP-006: 승인된 모듈로 전체 도시 구역 확대. 현재 DRAFT 유지.
- WP-007: 전체 HUD 레이아웃·결과 화면의 좌표/개발 용어 정리·최종 UI와 연출 마감. 현재 DRAFT 유지.
- 셀 20px, 시설 점유 40px, HP360/60, 적 수·피해·경로·연결 규칙은 보존. 표시 크기 변경이 필요하면 캔버스/pivot/돌출 범위를 기록하고 기존 점유를 침범하거나 다른 시설을 가리지 않게 검증한다.
- 붕괴 전 조작 기회 추가는 별도 기획 P-019에서 결정. 이 시각 계획으로 건설·경제·밸런스 변경을 승인하지 않는다.

## 제출할 증거

1. 같은 seed·명령·시뮬레이션 tick의 개선 전후 화면. 1080p/720p 각각 기본 표시와 라벨 없는 화면. 연속 캡처로 tick이 달라진 경우 차이를 명시하고 외곽선 효과의 통제 비교로 사용하지 않는다.
2. 기본 전투, 1,000체 군집, 붕괴 직후, 배치 가능/불가, 재배치 후 사격, 메뉴/승패 결과. 기본 런과 부하 유지 시나리오를 구분한다.
3. 건물/시설 근접 및 점유 격자 비교. 그림자·처마 때문에 이동/배치 가능한 셀을 벽으로 오인하지 않는지 확인한다.
4. 원본·프레임·규격·pivot·manifest와 기존 리소스 이력. 샘플 범위의 기존 에셋을 보존하며 교체 이유 기록.
5. 기존 회귀 및 F1/F2/F4 표시 모드 간 상태 일치. 렌더링 변경 후 동일 최종 release의 greybox/sample 이동·전투 성능 4조건을 기존 예산으로 검증. 창 표시 조건을 기록하고 다르면 기준선도 재측정.

## 판정과 다음 단계

- AC-02: 길·건물·내곽 구분과 점유 정합. AC-03: 시설/상태 무라벨 식별. AC-06: 군집·위협·배치·메뉴 가독성으로 연결한다.
- GPT는 실제 게임샷을 보고 PASS/FAIL/NOT RUN과 필요한 수정을 기록한다. 이미지는 확대 화면뿐 아니라 실제 표시 크기로 평가한다.
- 모든 필수 리소스와 기존 AC를 유지한다. 이 개선 묶음만 완료했다고 WP-005를 DONE으로 바꾸지 않는다.
- 사용자에게 동일 적용본의 스타일 방향을 확인받고, GPT 규격·가독성 검수까지 충족해야 AC-08 PASS. 단순 리소스 표시 확인을 승인으로 대체하지 않는다.
- 통과 후 WP-006 READY 명세 확정. 그 전까지 전체 맵 리소스 양산 보류.

근거: 사용자 게임샷 평가 및 계획 반영 요청, [기존 그래픽 평가](../../results/GRAPHICS_EVAL_WP005.md), [플레이 테스트 계획](../PLAYTEST_WP005.md). 기존 결과 수치는 해당 커밋의 기록이며 이 계획의 실행 결과가 아니다.
