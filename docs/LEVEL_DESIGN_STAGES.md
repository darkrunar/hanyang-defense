# 단계별 레벨 디자인

2026-09-28 · 설계 DRAFT · [공통 규칙](LEVEL_DESIGN_RULES.md)

Stage 번호는 학습 순서다. V0~V6은 검증 범위이므로 일대일 매핑하지 않는다. 아래 지도 좌표·웨이브 구성은 제작 지시안이며 생성된 실행 맵/플레이 PASS가 아니다. Stage001/003의 기존 에디터 템플릿은 재사용하고, 수정안은 별도 파일로 비교한다.

## 전체 진행

| Stage | 새로 배울 행동 | 유지할 행동 | 검증 범위 | 상태/의존성 |
|---|---|---|---|---|
| 001 성문 앞 첫 방어 | 적 경로를 보고 유효한 곳에 화차 배치 | 목표 보호 | V0/V1 | 기존 무지형 템플릿 기반, 실제 전투 연결 필요 |
| 002 밀려오는 적 | 압박이 높아질 때 화력 배치 판단 | 경로·목표 식별 | V1 | 별도 정식 fixture 필요 |
| 003 굽어진 접근로 | 지형의 긴 사격 구간 활용 | 압박 대응 | V1 | R-01 수정안 검증 필요 |
| 004 어디를 지킬 것인가 | 장승으로 경로와 집중 지점 선택 | 지형·화차 배치 | V1 | 설치 계약·두 경로 fixture 필요 |
| 005 싸우며 증설 | 보상으로 다음 방어 건설 | 공간 선택 | V2 | WP008 구현 SHA·통합 확인 뒤 |
| 006 떨어진 방어시설 | 연결의 이득과 비용 비교 | 건설·경로 판단 | V3 | 공유 관측 역할 채택 및 실제 발사 비교 뒤 |
| 007 성문이 버티는 동안 | 성문 공방 중 외부/내부 투자 | 경제·선택 | V4 | WP009 공성 계약·성문 HP 통합 뒤 |
| 008 깨진 방어선 재편 | 파괴 예고에 대응해 재건/재배치 | 앞선 공방·경제 | V4 | WP010 장승 파괴·재건 슬롯 확인 뒤 |

V5 도시 확장과 V6 런 변주는 성공 시 확보할 구역·보상·다음 판 차이가 미정이므로 이번 8단계의 확정 후속 레벨로 만들지 않는다. 장승 종류도 설화 명칭만으로 능력을 새로 배정하지 않는다.

## 공통 제작 좌표

- 현재 맵: 64×36 셀. 왼쪽 위 (0,0), 오른쪽 +x, 아래 +y. 아래 Rect 좌표는 양 끝 포함.
- 성 외곽: x24~39, y10~25. 목표 (31,17). 주 성문 (31,25),(32,25).
- 외곽 진입: x29~33,y35. 생성 중심 (31,40), 반경3. 현재 한 생성 중심·한 주 성문 계약 유지.
- 지도 경계·성벽 외부는 기본 빈 필드. 2×2 시설 후보는 왼쪽 위 좌표이며 점유·타깃 존·사거리 검사를 통과해야 채택한다.
- 같은 생성 좌표를 Stage 간 비교에 사용한다. stage_id가 seed를 바꾸는 기본 동작에 의존해 A/B를 비교하지 않는다.

```text
              성 내부
          ┌──────────┐
          │   목표   │
          │          │
          └────문────┘
               ↑       성문 앞 전투 구간
           지형/배치     Stage003부터 변화
               ↑
             진입점
────────────화면 하단────────────
          화면 밖 분산 생성
```

## Stage001 — 공방이 읽히는 첫 방어

**질문:** 적이 목표에 닿기 전에 어느 위치에서 쏘아야 하는가?

- 지도: 기존 flat_template 유지. 외부 장애물 없음. 화차 후보 A=(29,29), B=(34,26). 둘 다 2×2 설치 가능 여부와 실제 경로 위 적을 타깃할 수 있는지 먼저 확인한다. A는 조기 교전, B는 성문 앞 교전의 비교 후보이며 현재 존 구조가 이를 지원하지 않으면 존 설계를 별도 검토한다.
- 구성: 적 1종, 같은 화차 1기. 경제를 숨긴 무료 실험 fixture로 배치만 비교한다. 이것은 실제 캠페인 시작 자산을 바꾸는 결정이 아니다. 장승·봉수·공성 적 미도입.
- 흐름: 준비 중 접근 예고/목표 확인 → 소수 적으로 첫 명중 확인 → 같은 적의 짧은 집단 → 결과 확인. 구체 적 수는 실제 화력 프로필을 고정한 뒤 설정한다.
- 비교: 유효 사격 위치와 명백히 사격 구간을 벗어난 위치를 같은 조건으로 실행. 처치·첫 발사 시각·목표 피해를 기록한다. 실패 배치에서 재시작 후 같은 seed로 수정 가능하게 한다.
- 통과: 10초 안에 성문/목표 식별, 유효 배치에서 실제 처치 발생, 잘못된 배치와 목표 피해 또는 처치 결과 차이. 유효 배치까지 항상 패배하면 튜토리얼을 늘리기 전에 화력/노출 구간을 수정한다.
- 증거: 전체 지도, 첫 명중, 목표 피해 또는 방어 성공, 준비~결과 영상. 현재 실제 전투 NOT RUN.

## Stage002 — 같은 길, 다른 압박

**질문:** 적이 더 짧은 시간에 몰릴 때 어디에 화력을 집중할 것인가?

- 지도·적 종류·총수·화차 수/성능·물자 조건은 Stage001 기준으로 고정한다. 생성 반경은 그대로 둔다. 반경 변경만으로 다른 공격 방향을 가르친다고 주장하지 않는다.
- 새 변수는 생성률 하나: 기준 1.0×와 실험 1.25×. 먼저 별도 A/B 실행으로 효과를 확인한 뒤 낮은 압박 → 휴식 → 높은 압박의 학습 구성으로 편성한다.
- 전방 조기 사격과 성문 집중 사격의 생존 적 수·피해를 비교한다. 두 위치가 전혀 다른 결과를 만들지 못하면 출현량을 더 올리지 말고 공격 존과 노출 구간부터 재검토한다.
- 통과: 실험 조건에서 성문 앞 최대 생존 적 또는 도달 간격이 변하고, 배치 변경으로 처치/목표 피해가 개선되는 사례가 있다. 휴식 구간에는 다음 압박 예고를 확인할 수 있다.
- 단일 진입점에서 적을 임의로 두 방향으로 보내는 기능은 추가하지 않는다. 실제 Stage002 데이터와 전투 기록 모두 새로 제출한다.

## Stage003 — 지형 때문에 생기는 공격 기회

**질문:** 적이 돌아가는 동안 더 오래 공격할 자리는 어디인가?

- 기존 측면 장식 장애물을 그대로 성과로 세지 않는다. 수정안: 외부 장애물 하나를 **x28~35,y29~30**에 배치한다. 성문 아래 직선 접근을 가로막되 좌우 우회와 성문 접근은 남긴다. 바닥 경계/성벽과 연결하지 않는다.
- 예상 경로: 진입(31 부근,35) → 장애물 왼쪽 x27 이하 또는 오른쪽 x36 이상 → y28 부근 → 성문 → 목표. 실제 탐색의 동률 처리로 한쪽만 선택될 수 있으므로 양쪽 분산을 약속하지 않는다.
- 시설 후보: A=(25,29) 외부 조기 교전, B=(30,26) 성문 집결 교전. 장애물·성벽과 점유가 겹치지 않는지 확인한다. 같은 시설과 예산으로 두 배치를 비교한다.
- 적 편성은 Stage001 기준으로 되돌려 고정한다. 새 지형과 Stage002 최대 압박을 처음부터 겹치지 않는다.
- 통과: 동일 12개 생성 표본 중 **하나 이상 실제 경로 좌표가 바뀌고**, 모든 유효 생성 셀은 문/목표에 도달한다. 경로 변화 비율·길이 차이·집결 셀을 전부 보고한다. 이는 G1 최소선이며, G3에서는 두 배치의 노출 시간/발사/피해 비교로 지형의 의미를 별도 판정한다.
- 실패 시: 좌표 변경만 있고 공격 기회가 같으면 길을 더 늘리는 대신 화차 후보와 집결 위치를 조정한다. 제작 전 예상도이며 경로/전투 미검증.

## Stage004 — 장승으로 고르는 길

**질문:** 어느 길을 남겨야 화차가 더 잘 공격하는가?

- Stage003 장애물을 유지한다. 추가 고정 지형 x24~25,y31~34와 x38~39,y31~34를 놓아 장애물 양쪽에 폭2 이상의 통행 후보를 만든다. 단, 바깥 우회도 남으므로 '두 길만 존재'한다고 가정하지 말고 전체 경로를 검사한다.
- 장승 후보 A=(26,31), B=(36,31). 두 후보 중 한 곳에 같은 장승을 두는 비교부터 한다. 실제 전체 봉쇄나 포화 골목 설치 금지에 걸리면 거절 피드백을 확인하고 후보를 수정한다. 두 곳 동시 설치를 요구하지 않는다.
- 화차는 공통 위치로 고정해 장승 유무 → A/B의 경로·밀집·발사 차이를 분리한다. 현행 경로/설치 규칙만 사용하며 장승 파괴 적은 아직 등장시키지 않는다.
- 통과: 허용된 설치 하나가 실제 이동/집결 위치를 바꾸고, 고정 화차의 공격 기회나 목표 피해를 바꾼다. 완전 봉쇄는 현행 규칙대로 거절된다. A/B가 실질적으로 동등하면 선택 두 개 달성으로 기록하지 않는다.
- 지도 수정이 많아지면 장애물 추가만 한 대조군도 저장해 장승 효과와 구분한다.

## Stage005~008 — 기능 확인 후 확장할 설계

| 단계 | 공간·배치 설계 | 학습 흐름·선택 | 통과/실패 분기 |
|---|---|---|---|
| 005 | 통과한 Stage003 지도 재사용. 외부 공격 후보와 성문 후보 각각 2×2 이상 확보 | 작은 공격을 막고 물자를 받은 뒤 화차 증설 또는 저축. 다음 공격 전에 비용·부족액 표시 | 실제 지급→차감→배치→전투 기여 연결. 시작 자원+첫 보상이 최소 선택 시설 비용에 도달하는지 확인. 기존 WP008 가격·자산을 기준으로 하고 임의 재설정 금지 |
| 006 | Stage005 지도에서 경로·적은 고정. 경로 위 타깃 존을 직접 관측하는 지점과 사거리 안이지만 직접 관측 불가한 화차 위치 구성 | 같은 총비용의 연결 투자와 직접 화력 투자 비교. 단절 전후 발사 원인을 보여 줌 | 연결로만 생긴 사격과 추가 화력 대안을 모두 비교. 망의 필요/이득이 안 보이면 레벨을 강행하지 않고 역할 보류. 단순 맵 확대는 해법으로 확정하지 않음 |
| 007 | 단일 성문·외부 사격 구간·문 안 목표까지 완충 구간 유지. 내부 설치 공간 예약 | 외부 화력으로 성문 보존 또는 내부 방어 비축. 성문 체력과 파괴 예고 → 돌파 후 위험 변화 | 정상 방어 승리와 돌파 후 수습을 별도 fixture로 시험. 성문이 버티면 강제 파괴 금지. gate 셀 통과 미리보기는 공성 검증 아님 |
| 008 | Stage004 장승 경로와 Stage007 내부 공간 재사용. 파괴 후에도 목표까지 합법 경로 유지 | 공성 적 예고 → 집중 공격 또는 장승 손실 대비 → 파괴 시 새 길 대응 | 파괴 후 경로 갱신·구매 가능한 물자·설치 슬롯·실제 재건 확인. 회수 가능 초기 화차와 구매 화차를 구분. 붕괴가 반드시 발생해야 통과하는 구성 금지 |

Stage007/008의 대응 여유는 추측으로 '5초면 충분'이라 고정하지 않는다. 정상 속도에서 `위협 예고→인지→입력→효과 발생`을 측정하고, 적의 목표 도달 전 여유가 그 시간보다 긴지 검증한다. 타이머·핵심 HP 버퍼의 선택은 해당 공성 명세에 기록한다.

## 바로 다음 제작 요청

1. 기존 원본/증거 보존. 성 밖·벽·문 목표를 거절하는 검사 보완(R-02).
2. Stage003 수정안을 별도 fixture로 작성하고 같은 생성 좌표의 무지형 대조군과 경로 비교(R-01). Stage001의 정상 지도 검사를 함께 회귀.
3. Stage001 편집 맵을 실제 전투로 연결. 사용한 전투 프로필·타깃 존·승패·시설 배치를 결과에 명시. 기본 공방의 미결정 규칙에 의존하는 변경은 구현하지 말고 차이표 제출.
4. Stage001 정상 속도 영상과 배치 비교가 나온 뒤 Stage002 정식 데이터 → Stage003 전투 → Stage004 장승 비교 순서로 진행.
5. Stage005~008은 해당 기능 구현/리뷰 상태 확인 뒤 별도 WP 범위를 확정. 이번 요청으로 모두 동시 구현하지 않는다.

제출 파일: 스테이지 데이터, 공통 전투 설정 참조, seed와 생성 좌표, 자동 검사 로그, A/B 경로/사격/피해 JSON, 이미지, 정상 속도 영상, 단계별 PASS/FAIL/NOT RUN 및 체감 평가. 좌표 설계의 유효성과 실제 재미는 구현 후 각각 검증한다.
