# 스테이지별 맵 기획 테스트 체크리스트

맵을 먼저 `지형 없음`과 `지형 있음`으로 구분한다. 각 스테이지는 맵 에디터의 자동 검사와 실제 플레이 관찰을 모두 통과해야 한다. 자동 검사는 동선이 성립하는지를 확인하고, 플레이 테스트는 그 동선이 이해되고 재미있는지를 확인한다.

## 공통 확정 규칙

- 몬스터는 화면 바깥의 한 생성 중심을 기준으로 지정 반경 안에서 무작위 분산 생성된다.
- 몬스터는 외곽 진입점을 거쳐 화면 안으로 들어온다.
- 몬스터는 성벽을 통과하거나 넘을 수 없다.
- 성문은 성 안으로 들어가는 유일한 진입 지점이다.
- 생성 반경에서 추출한 모든 검증 표본이 `외곽 진입점 → 성문 → 최종 방어 목표`로 이동할 수 있어야 한다.
- 성벽·지형·생성 중심·반경을 바꿀 때마다 랜덤 표본 동선을 다시 검사한다.
- 자동 검사의 PASS와 플레이 경험 평가는 별도로 기록한다.

## Stage 001 — 일반 필드 기본 학습

목적: 지형 변수 없이 `화면 밖 랜덤 생성 → 필드 진입 → 성문 집결 → 성 안 진입` 규칙을 이해시키는 첫 스테이지.

에디터 설정:

- 맵 구분: `지형 없음`
- 외부 장애물: 없음
- 성문: 하나의 주 성문
- 생성 중심: 화면 하단 바깥 한 지점
- 생성 반경: 기본 3칸, 검증 표본 12개
- 외곽 진입점: 화면 하단 가장자리
- 최종 방어 목표: 성 안 중앙

자동 체크:

- [ ] 지형 없는 맵으로 저장된다.
- [ ] 외곽 경계와 성벽 외에 이동 장애물이 없다.
- [ ] 성문을 제외한 성벽 둘레가 닫혀 있다.
- [ ] 생성 중심과 랜덤 표본이 모두 화면 밖에 있다.
- [ ] 외곽 진입점이 화면 가장자리에 있다.
- [ ] 반경 안에 서로 다른 랜덤 생성 표본 12개가 만들어진다.
- [ ] 모든 랜덤 표본 경로가 외곽 진입점과 성문을 순서대로 통과한다.
- [ ] 모든 랜덤 표본 경로가 최종 방어 목표에 도달한다.

플레이 체크:

- [ ] 플레이 시작 10초 안에 방어할 성문을 알아볼 수 있다.
- [ ] 몬스터가 벽을 뚫거나 벽에 걸려 멈추지 않는다.
- [ ] 화면 밖에서 나타난 몬스터가 필드 안으로 쳐들어오는 흐름을 읽을 수 있다.
- [ ] 첫 배치 선택이 성문 방어 결과에 눈에 띄는 차이를 만든다.
- [ ] 성문 돌파 전과 후의 위험 변화가 명확하다.

## Stage 002 — 일반 필드 압박 변화

목적: 지형은 그대로 두고 생성 방향·웨이브 수·생성 속도만 바꿔 방어 배치의 차이를 검증한다.

자동 체크:

- [ ] Stage 001과 동일하게 외부 지형이 없다.
- [ ] 생성 중심이나 반경을 바꿔도 모든 랜덤 표본 경로가 성문을 통과한다.
- [ ] 웨이브 수와 초당 생성 수가 0보다 크다.
- [ ] 생성 반경 일부가 벽이나 맵 밖에 걸려 표본 수가 부족하지 않다.

플레이 체크:

- [ ] 웨이브마다 압박 방향의 차이를 알아볼 수 있다.
- [ ] 단순 수량 증가만이 아니라 배치 변경을 요구한다.
- [ ] 난도가 올라도 성문 방어라는 목적은 흐려지지 않는다.

## Stage 003 — 지형 도입

목적: 성문 규칙을 유지하면서 외부 지형이 접근 동선을 바꾸는 경험을 처음 제공한다.

에디터 설정:

- 맵 구분: `지형 있음`
- 지형: 하나 또는 두 종류의 단순 장애물
- 성문: 하나
- 생성 중심과 반경: 지형에 의해 접근 경로 차이가 드러나는 위치에 배치

자동 체크:

- [ ] 성벽 이외 지형 장애물이 하나 이상 있다.
- [ ] 지형 추가 후에도 모든 랜덤 생성 표본이 성문까지 연결된다.
- [ ] 지형이 성벽의 우회 진입로를 만들지 않는다.
- [ ] 지나치게 긴 단일 경로나 막힌 생성 위치가 없다.

플레이 체크:

- [ ] 플레이어가 지형 때문에 경로가 달라졌음을 시각적으로 이해한다.
- [ ] 지형을 활용한 배치 선택이 최소 두 가지 존재한다.
- [ ] 첫 지형 스테이지가 길 찾기 퍼즐처럼 과도하게 복잡하지 않다.

## Stage 004 이후 — 복합 지형

목적: 갈림길, 병목, 우회로를 조합하되 성문과 최종 방어 목표의 관계를 유지한다.

자동 체크:

- [ ] 모든 스폰의 유효 경로가 유지된다.
- [ ] 성문을 우회해 성 안으로 들어가는 경로가 없다.
- [ ] 수정 전후 경로 길이와 집결 위치를 비교했다.
- [ ] 저장한 스테이지를 다시 불러와도 동일한 검사 결과가 나온다.

플레이 체크:

- [ ] 지형을 보고 주요 전투 지점을 예측할 수 있다.
- [ ] 특정 방어시설 하나만 정답이 되지 않는다.
- [ ] 실패 원인이 지형·배치·화력 중 무엇인지 구분된다.

## 맵 에디터 실행

```powershell
godot --path . res://game/tools/map_editor.tscn
```

저장 파일은 Godot 사용자 데이터 폴더의 `stage_maps/<스테이지 ID>.json`에 생성된다. `검증·동선 테스트`는 체크리스트와 각 스폰의 성문 경유 경로를 동시에 표시한다.
