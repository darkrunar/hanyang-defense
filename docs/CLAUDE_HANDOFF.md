## 현재 상태 — 과거 WP-001 지시를 대체

- WP-001~004는 DONE. 엔진은 Godot 4.7.stable, Windows, 2D 탑다운으로 확정됐다. 엔진 선정이나 초기 프로토타입 구현을 다시 시작하지 않는다.
- WP-005는 **IN_PROGRESS / 전체 REVISE**. PR #11·#12는 WP-005 작업 브랜치에 반영됐다. PR #8은 main 병합 전이다.
- 실제 상태 PNG는17/35개 적용. 기본 시설4종과 비활성/단절4종, 바닥4프레임, 지붕/담장, 기본 적6상태×2프레임이 있다.
- 적 소멸 프레임 잘림, 비활성 시설의 도형 대체, 실제 리소스 F1/F2/F4 비교 누락은 보완됐다. 원본/적 프레임 경계/해시는 저장소에서 추적한다.
- 최신 회차4 결과 문서에는 구현 `079df43` 기준 회귀1,312 PASS / 0 FAIL, 동일 배포본의 성능4조건 PASS가 기록돼 있다. 과거 숨긴 창 측정과 회차4의 보이는 창 측정은 구분한다. 이 인계문은 해당 결과 기록을 요약하며 새 검증 실행을 의미하지 않는다.
- AC-03/04/05/07 PASS 기록, AC-01 FAIL, AC-02/06 전체 증거 미완, AC-08 NOT RUN. 전체 WP의 PASS나 DONE으로 확대 해석하지 않는다.

## 이번 작업 — WP-005의 남은 항목

먼저 최소 리소스의 잔여 목록과 사용 가능한 제작 도구를 확인하고 간단한 작업·검증 계획을 남긴 뒤 진행한다.

1. 필수 미제작 상태: 바닥 경계8타일, 성문, 화차 발사3프레임, 봉수 점등2프레임, 외곽/핵심 거점 각각 정상·피격·붕괴, 발사·탄착·붕괴 FX 각각3프레임. 정확한 계약은 ArtSet과 WP를 대조한다.
2. 연결·단절·회수·배치 표시는 WP에서 절차적 도형을 허용한다. PNG 누락 수만으로 전부 신규 이미지 제작 대상으로 간주하지 말고, 실제 표시와 manifest를 연결해 검증한다.
3. 생성 도구 접근이 가능하면 원본·전체 제작 지시·출처를 보존하며 샘플만 제작·적용한다. 접근 불가 항목은 ID·상태·규격·입력 원본을 명시해 GPT에 반환한다. 완료로 위장하거나 기존 그림을 무단 대체하지 않는다. 제작을 기다리는 동안 가능한 가져오기·검증 보완은 계속한다.
4. 어두운 길 위 적 대비, 작은 화면의 소등 식별, 지형 경계와 점유 정합을 보정한다. 전투 규칙·적 수·시설 점유·경로를 바꿔 문제를 감추지 않는다.
5. 실제 샘플의 근접/점유 비교, 두 해상도 메뉴/문자/배치 표시, 1000체 가독성을 검수한다. 사용자의 스타일 확인은 별도 실제 응답으로 기록한다.

WP-006 전체 전장 양산, WP-007 전체 UI/연출 마감, 경제·새 적·스킬·보스·음향·새 카메라 체계는 이번 범위에 추가하지 않는다. 새로운 기획 변경은 제안으로 분리한다.

## 구현·검증 원칙

- 기존20px 셀·40px 시설 점유, HP360/60,18시설,10존,seed20260913,유한 웨이브1140체와 메뉴 입력 해제 규칙을 보존한다.
- `game/core/` 시뮬레이션과 `game/scenes/` 표현을 분리한다. 아트 때문에 판정을 변경하지 않는다.
- 전용 비활성 원본은 `import_wp005_sources.gd`로 가져온다. 과거 파생 도구로 다시 덮어쓰지 않는다. `enemy_geometry.json`의 모든 프레임 경계를 검증한다.
- `tests/run_tests.gd`의 기존 회귀와 실제 리소스 F1/F2/F4 greybox/sample full_state 비교를 통과해야 한다. 상태 비교는 초기·붕괴 전후·재배치 후·종료 등 해당 시나리오의 체크포인트로 남긴다.
- `wp005_assets[_720]`, `wp005_dense[_720]` 등 기존 실제 캡처를 활용한다. dense 캡처는6배속이므로 HUD 순간 FPS를 성능 증거로 사용하지 않는다.
- 성능은 같은 최종 release·장비·창 표시 조건·1920×1080·vsync0에서 greybox/sample 각각 collapse_move/combat, warmup10초+measure60초로 측정한다. 측정 조건을 바꾸면 기준선도 다시 측정한다.
- 평균≥60FPS, p95≤25ms, 모든 측정 프레임 alive≥1000. frame_us_raw/alive_raw,6종 이벤트,구간 귀속·후보 평가·재배치 후 사격,메모리,구현SHA와exe 해시를 기록하고 검산한다. 생성 누계와 동시 생존 수를 혼동하지 않는다.
- 새 리소스가 들어오면 검산 도구의 파일 수 기준을 실제 manifest에 맞춰 갱신한다. 기존17개 수를 전체 제작 완료 조건으로 고정하지 않는다.
- 실패는 FAIL, 미실행은 NOT RUN. 공개 저장소에 인증정보·개인 절대 경로·권리 미확인 외부 에셋을 올리지 않는다.

기존 결과와 증거를 보존하고 새 회차 폴더에 저장한다. `results/WP-005-RESULT.md`에 다음을 추가한다.

- 설치·실행·가져오기·검증 재현 방법
- 리소스별 제작 상태·원본·규격·pivot·해시
- AC별 PASS/FAIL/NOT RUN과 증거
- 실제 화면·성능·알려진 한계·기획 변경 제안
- 사용자 확인 여부, 다음 WP 영향, PR #8 링크

코드 커밋 후 검증 결과를 별도 커밋으로 기록한다. 기존 작업 브랜치와 PR #8을 갱신하며, 분리 필요 시에만 새 Draft PR을 만든다. main에 직접 병합하지 않는다. 검증/필수 제작이 미완이면 IN_PROGRESS를 유지하고, 제출 조건을 갖추면 REVIEW로 전환해 이번 회차 GPT 판정은 PENDING으로 요청한다. 이전 리뷰를 덮어쓰거나 모든 필수 AC와 GPT PASS 전에 DONE으로 바꾸지 않는다.

Notion 연결이 가능하면 검증 커밋·GitHub 링크와 함께 현황을 갱신한다. 최종 응답에는 완료/미완 항목, 검증 결과, 결과 문서와 PR 링크, 바로 실행할 수 있는 경로를 제공한다.
